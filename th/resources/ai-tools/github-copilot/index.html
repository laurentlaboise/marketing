GitHub Copilot

GitHub Copilot เป็นผู้ช่วยเขียนโค้ดในไอดีอี เช่น VS Code และ JetBrains มีเติมโค้ดระหว่างพิมพ์ แชท และฟีเจอร์เอเจนต์หรือซีแอลไอตามที่ GitHub เอกสารไว้ สำหรับนักการตลาดจะใช้ได้เมื่อมีนักพัฒนาในทีม

GitHub Copilot คืออะไร?

GitHub Copilot คือผู้ช่วยเขียนโปรแกรมที่ทำงานในเครื่องมือพัฒนา ไม่ใช่แชทการตลาดสำหรับวางแผนสื่อ เอกสาร GitHub อธิบายว่าเติมโค้ดขณะพิมพ์ในไอดีอี คุยถามเรื่องโค้ดผ่าน Copilot Chat และมีช่องทางในเทอร์มินัลหรือโหมดเอเจนต์ตามแผนที่บัญชีเข้าถึงได้ ส่วนขยายรองรับสภาพแวดล้อมที่ GitHub ระบุ เช่น Visual Studio Code ชุด JetBrains และอื่น ๆ ในรายการทางการ ตรวจรายการไอดีอีปัจจุบันบนหน้าผลิตภัณฑ์

GitHub แยกแผนสำหรับบุคคล ธุรกิจ และองค์กร รายละเอียดสิทธิ์ นโยบาย และการจัดการไลเซนส์ต่างกัน เราไม่ใส่ราคาต่อที่นั่ง ไดเรกทอรีนี้บันทึกโมเดลเป็นแบบชำระเงินสำหรับงานจริง ชั้นทดลองหรือสิทธิ์เพิ่มเติมให้ดูบนหน้าแผนของ GitHub โดยตรง เพราะชื่อแผนและเครดิตโมเดลมีการปรับ

นักการตลาดที่ไม่มีคนเขียนโค้ดจะกด Copilot แล้วได้เว็บร้านค้าสมบูรณ์ไม่ได้ สิ่งที่เครื่องมือนี้ช่วยในเอเจนซีคือให้นักพัฒนาเขียนหน้าแลนดิ้ง ตัดต่อแท็กวัดผล หรือแก้สคริปต์เล็กบนไซต์ลูกค้าได้เร็วขึ้น ยังต้องมีคนอ่านโค้ด ตรวจสิทธิ์ไลบรารี และตรวจว่าไม่มีการวางความลับในพรอมต์

Copilot แนะนำชิ้นโค้ดจากแบบรูปที่โมเดลเรียนรู้มา ชิ้นนั้นอาจคล้ายโค้ดสาธารณะที่มีใบอนุญาตต่างกัน GitHub มีเอกสารเรื่องข้อเสนอแนะและนโยบายทรัพย์สินทางปัญญา ทีมต้องอ่านหน้าปัจจุบันและตั้งนโยบายภายในว่าโค้ดที่ Copilot เติมต้องผ่านการรีวิวเหมือนโค้ดที่จ้างฟรีแลนซ์ อย่ากดรับทั้งไฟล์แล้วขึ้นโปรดักชัน

ห้ามวางคีย์เอพีไอ รหัสผ่านโฆษณา โทเคนวัดผล หรือไฟล์รายชื่อลูกค้าลงในแชทของ Copilot แม้จะอยากให้ช่วยดีบัก การรั่วไหลของความลับมีราคาสูงกว่าเวลาที่ประหยัดได้จากการเติมโค้ด ใช้ตัวแปรตัวอย่างและข้อมูลปลอมในพรอมต์

สิ่งที่เอกสาร GitHub ระบุ

  • เติมโค้ดแบบอินไลน์ในไอดีอีที่รองรับ
  • Copilot Chat สำหรับถามและแก้โค้ดในไอดีอีและบนพื้นผิวที่ GitHub เปิดไว้
  • การใช้งานผ่านซีแอลไอหรือเทอร์มินัลตามที่เอกสารฟีเจอร์อธิบาย
  • โหมดเอเจนต์ในไอดีอีที่ให้ช่วยแก้หลายไฟล์โดยคุณยังเป็นคนอนุมัติ
  • แผนบุคคล ธุรกิจ และองค์กร พร้อมเครื่องมือนโยบายในแผนองค์กร

ชุดฟีเจอร์ไม่เท่ากันทุกแผน เปิด หน้า Copilot ของ GitHub และเอกสารประกอบก่อนซื้อให้ทั้งทีมพัฒนา

เมื่อไหร่ที่นักการตลาดได้ประโยชน์

  • มีนักพัฒนาที่ต้องขึ้นหน้าแลนดิ้งหรือแก้แท็กวัดผลบ่อย
  • ต้องการร่างโครงเอชทีเอ็มแอลหรือสคริปต์วิเคราะห์ให้นักพัฒนาตัดต่อ
  • ทีมมีนโยบายรีวิวโค้ดและที่เก็บความลับแยกจากพรอมต์

สิ่งที่ไม่ควรทำ

  • อย่าวางความลับ คีย์ หรือข้อมูลลูกค้าในพรอมต์
  • อย่าขึ้นโปรดักชันด้วยโค้ดที่ไม่ได้ตรวจใบอนุญาต
  • อย่าซื้อที่นั่งให้ทั้งแผนกคอนเทนต์ถ้าไม่มีใครเปิดไอดีอี

เวิร์กโฟลว์กับนักพัฒนาในเอเชียตะวันออกเฉียงใต้

เอเจนซีในเวียงจันทน์และกรุงเทพฯ มักมีนักพัฒนาหนึ่งหรือสองคนที่รับทั้งเว็บลูกค้า แท็กพิกเซล และหน้าขอบคุณ Copilot ช่วยคนกลุ่มนี้ลดงานพิมพ์ซ้ำ เช่น โครงฟอร์ม บล็อกหัวข้อ หรือการเรียกเอพีไอที่เอกสารสาธารณะมีตัวอย่าง นักกลยุทธ์ยังเขียนบรีฟหน้าที่ต้องการเป็นภาษาคน แล้วให้นักพัฒนาแปลงในไอดีอี ไม่ใช่ให้นักการตลาดคุยกับ Copilot เองแล้ววางไฟล์ขึ้นโฮสต์

งานที่เห็นผลเร็วคือหน้าแลนดิ้งแคมเปญภาษาไทยที่มีฟอร์มไปยังไลน์หรือวอทส์แอปป์ Copilot ช่วยร่างเอชทีเอ็มแอลและซีเอสเอสตั้งต้น แต่วรรคตอนภาษาไทย การตัดคำ และการรองรับฟอนต์ท้องถิ่นต้องคนดูบนมือถือจริง การเติมโค้ดไม่ได้รู้ว่าปุ่มสีไหนผ่านแบรนด์ไกด์ของโรงแรมลูกค้า ให้ดีไซเนอร์ล็อกโทเคนสีก่อน แล้วค่อยให้โมเดลช่วยจัดโครง

แท็กวัดผล เช่น ส่งอีเวนต์เมื่อกดปุ่มจอง เป็นอีกงานที่นักพัฒนาใช้แชทช่วยเขียน แต่ค่าที่ส่งเข้าพิกเซลต้องตรงกับข้อตกลงในบัญชีโฆษณา ถ้าระบุชื่ออีเวนต์ผิด รายงานจะว่างทั้งที่คลิปโฆษณาวิ่ง กำหนดชื่ออีเวนต์ในบรีฟด้วยมือ แล้วให้ Copilot ช่วยเฉพาะไวยากรณ์ของโค้ด อย่าให้โมเดลตั้งชื่อเมตริกแทนทีมสื่อ

เมื่อได้ชิ้นโค้ด ให้ตรวจใบอนุญาตของแพ็กเกจที่ถูกเสนอให้ติดตั้ง อย่าติดตั้งไลบรารีที่แชทแนะนำโดยไม่อ่านหน้าแพ็กเกจ โดยเฉพาะงานลูกค้าที่ต้องโฮสต์ในประเทศหรือมีข้อกำหนดข้อมูล บันทึกในพูลรีเควสต์ว่าส่วนใดมาจากคำแนะนำของ Copilot เพื่อให้ผู้รีวิวรู้ว่าต้องอ่านละเอียด

ความลับที่พบบ่อยในออฟฟิศเอเจนซีคือโทเคนของจีทีเอ็ม คีย์ของบริการอีเมล และรหัสเอฟทีพี วางสิ่งเหล่านี้ในตัวจัดการความลับหรือตัวแปรสภาพแวดล้อม ห้ามวางในคอมเมนต์โค้ดและห้ามวางในแชท ถ้าต้องให้ Copilot ช่วยดีบัก ให้ทำสำเนาไฟล์ที่ลบค่าจริงออกก่อน

แผนธุรกิจและแผนองค์กรมีเครื่องมือให้นโยบายที่ GitHub เอกสารไว้ เหมาะเมื่อเอเจนซีมีลูกค้าหลายรายและไม่ต้องการให้โค้ดลูกค้าปนในที่นั่งส่วนบุคคลที่ผูกบัญชีส่วนตัว คุยกับฝ่ายพัฒนาว่าจะผูก Copilot กับองค์กร GitHub ของบริษัทอย่างไร อย่าให้ฟรีแลนซ์ใช้ที่นั่งส่วนตัวกับรีโปลูกค้าโดยไม่มีสัญญา

ในโฮจิมินห์และกรุงเทพฯ มีตลาดฟรีแลนซ์เขียนเว็บจำนวนมาก Copilot ไม่ได้แทนการจ้างคนที่เข้าใจภาษาและโฮสติ้งท้องถิ่น แต่ลดเวลาคนที่มีอยู่แล้ว ถ้าทีมคุณยังไม่มีนักพัฒนา การซื้อ Copilot จะไม่แก้หน้าเว็บที่โหลดช้าหรือฟอร์มที่ส่งไม่ถึงไลน์ ให้จ้างคนก่อน แล้วค่อยใส่เครื่องมือคู่เขียนโค้ด

สรุปสำหรับแผนกมาร์เก็ตติ้งคือ Copilot เป็นเครื่องมือของห้องพัฒนา ไม่ใช่ของห้องคอนเทนต์ มีประโยชน์เมื่อมีคนอ่านโค้ดเป็น ช่วยร่างหน้าแลนดิ้งและสคริปต์วัดผล ต้องรีวิวใบอนุญาต และต้องแยกความลับออกจากพรอมต์ ถ้าเงื่อนไขนี้ยังไม่ครบ ให้เก็บงบไปที่โฮสติ้งและการตรวจเว็บบนมือถือจริงก่อน
